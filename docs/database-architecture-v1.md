# Deckun — Database Architecture V1

**Spec references:** sections 44, 45, 53, 64
**Goal:** a production-ready PostgreSQL schema (with SQLite compatibility for local dev) that enforces Deckun's business rules server-side.
**Working DB:** PostgreSQL (production-managed via AWS RDS, per `docs/decisions.md`). Local dev/test uses SQLite (`sqlite:///deckun.db`) with cross-database-compatible SQLAlchemy types.
**Money:** stored as integer **paise** (`INTEGER`) everywhere — never floats and never `NUMERIC` in V1. Conversion happens at the boundary.
**Deletes:** never hard-delete business records. Products, variants, images, reviews, orders and order items use a status enum or `is_active` flag.

---

## 1. Concepts this document enforces

This schema is the single source of truth for stock, order status and payment state. It enforces:

- **Order-locking rule (spec §19, §47):** once an order reaches `out_for_delivery`, no customer edit or cancel is allowed (enforced in code, but the `order_status_history` audit trail makes every change auditable).
- **Stock safety (spec §20):** stock is non-negative; reductions happen via atomic conditional updates; every change is logged in `inventory_movements`.
- **Price-snapshot rule:** order items capture name, variant name, unit price and discount at purchase time, so later product edits never rewrite history.
- **No oversell of exact values:** the public catalogue API exposes only `in_stock` / `low_stock` / `out_of_stock`, never raw counts.
- **Idempotency (spec §54):** a Razorpay `payment_id` is unique; raw webhook events are stored in `payment_events` so duplicates are safe.

## 4. Enum types (PostgreSQL)

> For SQLite these map to `VARCHAR` / `TEXT` with `CHECK` constraints generated by Alembic; SQLAlchemy `Enum(..., name=...)`.

- `product_status`: `active`, `hidden`, `archived`
- `order_status`: `placed`, `confirmed`, `preparing`, `out_for_delivery`, `delivered`, `cancelled`
- `payment_status`: `pending`, `paid`, `failed`, `cancelled`, `refunded`
- `payment_method`: `cod`, `online`
- `order_source`: `website`, `whatsapp`
- `review_status`: `pending`, `approved`, `hidden`
- `notification_type`: `new_order`, `order_confirmed`, `order_delivered`, `low_stock`, `review_pending`, `payment_failed`
- `otp_type`: `password_reset`

## 7. Design rules (summary of spec §1.3 key rules)

1. **Money** — all monetary columns are `INTEGER` paise. No floats.
2. **Order item snapshot** — `product_name`, `variant_name`, `unit_price`, `discount_amount`, `quantity` captured at purchase; never updated.
3. **Product status** — `active` / `hidden` / `archived`; no hard deletes. `archived` products still join to historical orders.
4. **Variant model** — if `products.has_variants = true`, pricing and stock live on `product_variants`; the product's `base_price` is NULL.
5. **Stock** — `CHECK (stock >= 0)`; reductions via atomic conditional updates (`UPDATE ... SET stock = stock - :qty WHERE id = :id AND stock >= :qty`).
6. **Order status** — `placed → confirmed → preparing → out_for_delivery → delivered`; cancel allowed before `out_for_delivery`. Separate `payment_status` (`pending/paid/failed/cancelled/refunded`), `payment_method` (`cod/online`), `order_source` (`website/whatsapp`).
7. **Uniqueness** — `users.mobile_number`, `admin_users.email`, `orders.order_number`, `payments.razorpay_payment_id`.
8. **Reviews** — one per user per product; linked to a delivered order item.
9. **Specifications** — flexible key/value rows per product.
10. **Images** — store object-storage URL/key, sort order, alt text only.
11. **Timestamps** — `created_at` / `updated_at` on every table; soft-state fields instead of deletes.
12. **Indexes** — on slugs, foreign keys, `orders.status`, `orders.created_at`, `users.mobile_number`.

## 8. Testing strategy (maps to plan §1.5)

| Test | What it checks |
| --- | --- |
| Negative stock | inserting `stock = -1` or reducing below 0 is rejected by `CHECK` |
| Duplicate mobile | inserting two users with same `mobile_number` is rejected |
| Duplicate order number | generating a duplicate `order_number` is rejected |
| Invalid order status | setting `status` to an unknown value is rejected by the enum |
| Archived product history | archived products still join to `order_items` (RESTRICT on FK, no data loss) |
| Today's orders query | `SELECT COUNT(*) FROM orders WHERE created_at >= today AND status = 'placed'` returns correct count |
| Low-stock query | `SELECT * FROM product_variants WHERE stock <= (SELECT setting_value FROM settings WHERE setting_key='low_stock_threshold')` |
| Idempotency | inserting a duplicate `razorpay_payment_id` is rejected |
| Review uniqueness | second review by same user on same product is rejected |
